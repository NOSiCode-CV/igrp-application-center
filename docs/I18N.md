# Internationalisation (i18n)

The app uses **next-intl 4 without i18n routing** through `@igrp/framework-next/i18n`: the locale is resolved per request and never appears in the URL. The framework owns the mechanics (cookie, providers, format helpers, CLI); its guide is `templates/demo-v1/docs/I18N.md` in [igrp-framework-nextjs](https://git.nosi.cv/igrp-3_0/igrp-framework-frontend/igrp-framework-nextjs). This page covers what is specific to the Application Center.

## Model

| Concept | Value |
|---|---|
| Platform locales | `pt`, `en`, `fr`. Fixed. |
| Default locale | `pt`. Its catalog (`messages/pt.json`) is complete and types every key. |
| Format locales | `pt-CV`, `en-GB`, `fr-FR` by default; per deployment via `IGRP_FORMAT_LOCALES` (always region-qualified, e.g. `pt-PT`). Drive dates, numbers and `<html lang>`. |
| Time zone | `IGRP_TIME_ZONE`, default `Atlantic/Cape_Verde`. Applies on server and browser. |
| Resolution | **Session-first**: `session.user.locale` → `IGRP_LOCALE` cookie → `Accept-Language` → `pt`. |

`IGRP_FORMAT_LOCALES` and `IGRP_TIME_ZONE` are the only formatting settings and are read only in `src/i18n/index.ts` (see `.env.example`).

## Where each piece lives

| File | Role |
|---|---|
| `src/i18n/index.ts` | `igrpDefineI18n(...)`: locales, format locales, time zone, `getSessionLocale`, `persistLocale`. Server-only; middleware must not import it. |
| `src/i18n/request.ts` | next-intl request config, registered in `next.config.ts`. |
| `src/i18n/actions.ts` | `setLocale` server action, passed to the switchers. |
| `src/i18n/global.d.ts` | Types `useTranslations` keys from `pt.json` plus the framework namespaces. |
| `src/i18n/status.ts` | `useStatusLabel`, `useStatusOptions`: translated labels for API status codes (`common.status.*`). |
| `src/i18n/session-locale-switcher.tsx` | Switcher for authenticated pages; awaits the session update before the refresh. |
| `src/i18n/messages/{pt,en,fr}.json` | Catalogs. One top-level namespace per feature, nested camelCase keys, ICU. |

## Changing the language

- **Saving.** `persistLocale` calls `PUT /api/users/me/locale` (`updateCurrentUserLocale` in `src/actions/access-client.ts`). It skips the API when there is no session or auth bypass is on; then only the cookie changes.
- **Cookie sync.** `src/middleware.ts` calls `igrpSyncLocaleCookie` with the token's locale (`resolution: "session-first"`), so sessionless pages such as login follow the user's choice.
- **Switchers.** The authenticated layout (`src/app/(igrp)/layout.tsx`) and the invite layout (invite visitors have a session) use `SessionLocaleSwitcher`; only login uses the plain `IGRPLocaleSwitcher`.

## Translating a feature

1. Add a camelCase namespace (`oauthClients`, `serviceAccounts`) to `pt.json`, `en.json` and `fr.json`. `check-catalogs` fails on any key missing from en or fr.
2. Translate every user-facing string: JSX text, `aria-label`, `title`, `placeholder`, toasts, confirm dialogs, empty states, column headers, Zod messages.
3. Keep the pt wording exactly as the literal it replaces. Do not swap in a shared key whose text differs (`common.unknownError` is not "Erro desconhecido"); add a feature key.
4. Client: `useTranslations("ns")`. Server: `await getTranslations("ns")` from `next-intl/server`.
5. Zod schemas take a translator (`(key) => string`) instead of literals (see `src/features/applications/app-schemas.ts`). API enum codes map to keys in a per-feature `lib/i18n.ts` (see `src/features/users/lib/i18n.ts`). Status codes stay API values; use `useStatusLabel` / `useStatusOptions`.
6. Dates, numbers, sorting: `useIGRPFormat()` (client) or `igrpFormatDate(value, await igrpResolveFormatLocale(i18n), undefined, i18n.timeZone)` (server). Never `useFormatter` and never a hardcoded region.
7. Add the feature's folders to the `lint:i18n` script in `package.json`.
8. Delete dead files instead of translating them (grep `src` for importers first).

## Checks

`pnpm lint:i18n` (also part of `build`) runs `igrp-i18n check-catalogs` (orphan keys, invalid ICU, argument parity with `pt`, coverage) and `igrp-i18n check-literals` over the folders listed in `package.json`, which include `src/components`. Mark a literal that is not language (a parsed token, a fixed formatter locale) with `// igrp-i18n-ignore: <why>`.

`src/__tests__/i18n/catalogs.test.ts` fails when an en value equals its pt value, to catch English text left in pt. Genuine cognates and protocol terms go in its `ALLOWED` list.

## Testing

`src/test-setup.ts` wraps every render in `IGRPIntlTestProvider` with `pt`, so existing assertions use pt text. To render another locale:

```tsx
import { renderWithIntl } from "@/__tests__/helpers/intl";
renderWithIntl(<Page />, { locale: "en" });
```

Add one English-render test per feature's main page, plus one for any dialog or form with its own strings. Build mock data at module scope: unstable mocked query data makes Vitest run out of memory.
